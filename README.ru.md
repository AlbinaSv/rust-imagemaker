# rust-imagemaker

![Rust](https://shields.io/badge/rust-2024-orange.svg)
![License](https://shields.io/badge/license-MIT-blue.svg)
![Platform](https://shields.io/badge/platform-Linux%20%7C%20Windows%20%7C%20macOS-lightgrey.svg)

Универсальный высокопроизводительный CGI-ресайзер изображений, написанный на Rust и разработанный для веб-сайтов и приложений. Он работает как автономный микросервис динамической обработки и кэширования графики «на лету», который можно подключить к *любому* движку или CMS без изменения исходного кода самого сайта.

## 💡 Мотивация и описание проблемы

Каждый разработчик сталкивается с проблемой, когда при редизайне полностью трансформируется внешний вид сайта, изменяются размеры и пропорции иконок или добавляются их новые варианты. Особенно травматично, если у вас под управлением интернет-магазин с тысячами товаров, и вам нужно одномоментно переделать абсолютно все миниатюры изображений.

Данный скрипт, работающий в режиме CGI, помогает быстро, эффективно, раз и навсегда решить эту задачу. 

### Как это работает на практике:
Допустим, все исходные изображения лежат в папке `/images`, а в базе данных хранится только чистое название файла для каждого товара (например, `hash12345.jpg`).

Вам достаточно в HTML-коде страницы дать ссылку на иконку в нужном вам размере:
```html
<img src="/images/icons/320x240/hash12345.webp" alt="Изображение товара">
```

После быстрой настройки конфигурации всё управление ложится на плечи сервера:
1. Веб-сервер запрашивает картинку по указанному пути `/images/icons/320x240/hash12345.webp`.
2. Если готового файла в кэше еще нет, `.htaccess` мгновенно перенаправляет задачу нашему Rust-скрипту.
3. 🛡️ **Защита от DDoS-атак и переполнения диска:** Скрипт никогда не генерирует изображения произвольного размера, переданного извне. Он обрабатывает **только строго заданные в `config.toml` варианты размеров** (белый список). Если в адресной строке запрошен сторонний размер, скрипт сразу отклонит запрос.
4. Скрипт бёрёт исходный оригинальный файл `/images/hash12345.jpg`, генерирует оптимизированное изображение в разрешенном размере `320x240`, накладывает вотермарк и физически сохраняет его по адресу `/images/icons/320x240/hash12345.webp`.
5. В следующий раз при обращении по этой ссылке веб-сервер отдаст картинку как обычную статику, вообще не нагружая процессор и не запуская Rust.

Если дизайнер снова изменит внешний вид сайта, вам больше не нужно запускать тяжелые скрипты перенарезки. Вы просто **стираете папку с кэшем (`/icons`) вместе со всем содержимым**, указываете в конфиге новые допустимые размеры и меняете пути в HTML. Кэш восстановится сам на лету по мере заходов пользователей.

## 🚀 Быстрый старт: Использование готовых файлов

Те, кто не знаком с компиляцией кода или не хочет самостоятельно собирать проект из исходников, может воспользоваться скомпилированными рабочими файлами под разные операционные системы.

Вам нужно сделать всего 4 простых шага:

### Шаг 1. Скачайте нужный файл
Перейдите в правое меню репозитория в раздел **Releases** и выберите один из трёх готовых вариантов под вашу систему:
* `rust-imagemaker-linux-x86_64` — для запуска на серверах под Linux-подобными ОС (используется на 99% обычных виртуальных хостингов, таких как Макхост, Timeweb и др.).
* `rust-imagemaker-windows-x86_64.exe` — для работы на серверах под управлением Windows Server (IIS).
* `rust-imagemaker-macos-arm64` — для локального тестирования и разработки на компьютерах Mac (Apple Silicon).

### Шаг 2. Размещение и обязательное переименование
Положите скачанный файл в ту директорию на сервере, из которой ваш хостинг разрешает запуск CGI-скриптов (чаще всего эта папка называется `cgi-bin`). 

**Важно:** После загрузки файл необходимо обязательно переименовать:
* На Linux и macOS переименуйте файл в: **`rust-imagemaker`** (без каких-либо расширений в конце).
* На Windows Server переименуйте файл в: **`rust-imagemaker.exe`**

### Шаг 3. Выставьте права доступа (для Linux / macOS)
Через FTP-клиент (например, FileZilla) или файловый менеджер хостинга обязательно установите для загруженного файла `rust-imagemaker` права доступа **`755`** (разрешение на исполнение). Без этого сервер выдаст ошибку *500 Internal Server Error*.

### Шаг 4. Настройка конфигурации и сервера
1. Скопируйте шаблон конфигурации из папки `examples/config.toml.example` в папку к вашему бинарнику, переименовав его в **`config.toml`**, и настройте пути.
2. Скопируйте правила перенаправления из папки `examples/.htaccess.example` в ваш основной файл **`.htaccess`** в корне сайта.

## 📁 Настройка путей и шаблоны конфигурации
Проект спроектирован максимально гибко. Вы можете настраивать структуру каталогов под любые нужды:
* 📂 **Полная свобода расположения кэша:** Папка для сохранения готовых превью (`icons`) **не обязана лежать внутри папки с исходными картинками**. Она может находиться абсолютно в любом месте файловой структуры вашего сервера. Главное — указать точный относительный или абсолютный путь к ней в переменной `cache_dir` внутри `config.toml`.
* 🖼️ **Размещение заглушки:** Параметр `fallback_image = "no-image.png"` задает имя файла-заглушки, который будет автоматически показан пользователю, если оригинальный файл товара отсутствует. Этот файл **должен лежать в той же самой папке, где находятся все ваши исходные оригинальные изображения** (`source_dir`).

Готовые шаблоны конфигураций находятся в репозитории:
* `examples/config.toml.example` — подробный файл конфигурации с комментариями к каждой строке на английском языке (настройки путей, белого списка размеров, режимов ресайза `contain`/`cover`/`stretch` и вотермарка).
* `examples/.htaccess.example` — готовые правила перенаправления для веб-сервера Apache.
